# Исправления бэкенда Demotest1(11)

Рабочая папка: Monochrome_Planet-X_and_SPHEREx-Demotest1(11).
Все 65 файлов фронтенда из локальной копии сохранены без изменений (SHA-256).
Перед публикацией восстановлены 12 отсутствовавших файлов из удалённой Demotest1,
включая i18n и canvas-компоненты. Diff frontend относительно родительского коммита
ветки пуст: опубликованный фронтенд сохраняется целиком.
Публичные модели OpenAPI и список маршрутов сохранены. Обновлены экспорт OpenAPI и
сгенерированные типы API-клиента: у readiness документирован HTTP 503 без worker.

## Исправления

- IRSA/CADC: до трёх попыток при временных HTTP/сетевых сбоях. Retry-After в секундах
  и формате HTTP-date учитывается; долгую задержку нельзя обойти ранним повтором.
- Ошибки содержат причину, HTTP-статус и контекст наблюдения, вместо общего сообщения
  IRSA is unavailable or rejected the request. Для поиска сохраняется стандартная
  оболочка error с request_id и, при наличии, заголовок Retry-After.
- Некорректные строки SIA и CADC, редиректы без адреса, некорректные byte ranges
  и изменение Last-Modified куба обрабатываются явно. Allowlist URL сохранён.
- POST одинаковой задачи возвращает ID уже активной задачи. Готовые результаты
  кешируются на 900 секунд с проверкой наличия всех файлов. Ошибочные результаты
  не кешируются; настройки провайдера/коллекций разделяют кеши.
- Worker проверяет действительность lease при heartbeat и публикации результата;
  потерявшая владение попытка останавливается. Новые lease по умолчанию 120 секунд.
  Штатная остановка возвращает текущую задачу в очередь. Общий deadline — 600 секунд;
  для спектра дополнительно действует прежний deadline 300 секунд.
- Readiness проверяет свежий heartbeat worker с той же конфигурацией. Отсутствие worker
  даёт HTTP 503. Liveness API независим от worker и архива.
- Асинхронный поиск не выполняет блокирующие операции SQLite в HTTP event loop.
- Миграция SQLite v1 → v2 добавляет служебные таблицы без удаления прежних задач.

## Внешние и остающиеся ограничения

При живой проверке SIA с минимальным запросом, DR1 и DR1+QR3, а также TAP-сервис IRSA
возвращали HTTP 502 Proxy Error / Error reading from remote server. Отдельная загрузка
куба поддерживала HTTP 206 и спектр извлекался успешно. Это текущий внешний сбой,
а не доказательство неправильных координат или ошибки фронтенда. Код корректно
повторяет временные ошибки и сообщает отказ; доступность IRSA локально не гарантируется.
Документация адресов сервисов: https://irsa.ipac.caltech.edu/spherex-archive-documentation/spherex-data-access/

Научная методика не менялась: спектр остаётся поверхностной яркостью пикселя мозаики;
нет выдуманных погрешностей, заполнения пропусков, классификации атмосферы или
подмены архива demo-данными. Кеш готового результата не перепроверяет ETag источника.
Синхронный расчёт в Python-потоке нельзя принудительно остановить; при отмене его
поздние файлы остаются изолированными и не публикуются. Персональные квоты и
автоматическая очистка старых файлов по-прежнему требуют отдельной настройки эксплуатации.
