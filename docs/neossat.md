# Подключение NEOSSat

NEOSSat доступен одновременно со SPHEREx через `source=neossat`. Менять
`SPHEREX_PROVIDER` не требуется: эта настройка относится к основному источнику SPHEREx.
Обработчик задач выбирает адаптер по `request.source`.

## Запросы

Поиск реальных публичных наблюдений:

```text
GET /api/v1/observations?source=neossat&ra=244.32768&dec=-16.46982&radius_deg=0.01&mjd_min=60900.49&mjd_max=60900.52&limit=10
```

Ответ использует общие модели наблюдений. `provider=neossat`, `synthetic=false`,
`collection=NEOSSAT`. `product_type` указывает COR или CORD, `exposure_seconds` —
длительность экспозиции, если архив её предоставил. `access_url=null`: актуальная
ссылка получается через DataLink при загрузке. Временные подписанные URL не сохраняются.
Фильтры длин волн пока доступны только для SPHEREx; для NEOSSat они возвращают 422.

Вырезка или blink создаются через существующую очередь:

```json
{
  "source": "neossat",
  "kind": "blink",
  "observation_ids": ["<первый ID из поиска>", "<второй ID из поиска>"],
  "ra": 244.32768,
  "dec": -16.46982,
  "fov_deg": 0.1,
  "size_px": 256,
  "subtract_zodi": false,
  "reject_flags": 0
}
```

Для `cutout` нужен один ID. Опрос статуса и скачивание PNG/FITS/GIF работают через
обычные `/api/v1/jobs`. Смешивать ID разных миссий в задаче нельзя.
Для NEOSSat обязательно указать `subtract_zodi=false` и `reject_flags=0`:
параметры ZODI и битовые маски SPHEREx к нему неприменимы.

## Что происходит с данными

Адаптер запрашивает публичный CADC ObsTAP `ivoa.ObsCore`, затем использует DataLink
для поиска файла с семантикой `#this`. Принимаются только продукты COR/CORD с
`calib_level>=2`. Загрузка ограничена по размеру; разрешены конкретные CADC/CANFAR
адреса и проверяемые перенаправления, без пользовательских URL.
Скачивается один целый обработанный FITS на кадр, вырезка строится локально.

Обработка читает изображение из primary HDU, проверяет celestial WCS и переводит
его на общую ICRS/TAN сетку методом ближайшего соседа. Он сохраняет выбранные
значения пикселей, но не является фотометрически сохраняющей поток репроекцией.
Без WCS выравнивание завершается ошибкой; положение не придумывается по центру снимка.

Результат хранит отсчёты детектора (ADU/counts), а не MJy/sr. При отсутствии BUNIT
принимается ADU согласно руководству NEOSSat; несовместимые единицы отклоняются.
Выходной FITS содержит IMAGE и COVERAGE. Дисперсия и FLAGS не создаются, поскольку
этот путь обработки не имеет соответствующих достоверных слоёв.
PNG/GIF используют общую шкалу яркости для выбранных кадров.

COR включает обрезку и коррекцию overscan, CORD дополнительно вычитает тёмный кадр.
Эти продукты, экспозиции и режимы сопровождения могут отличаться: изменения яркости
в blink не доказывают переменность. Архивная WCS может основываться на оценке ориентации
аппарата; дополнительная астрометрическая привязка пока не выполняется.
Операции stack/difference NEOSSat пока возвращают 422. Для них нужны проверенные
правила нормировки, калибровки, качества и переноса неопределённостей.

## Проверка и источники

```text
uv run python scripts/verify_neossat.py
```

Скрипт ищет два разных наблюдения в выбранном тестовом поле и запускает реальную
цепочку CADC → DataLink → FITS → blink. Результаты каждого запуска сохраняются отдельно
в `data/neossat-validation`. Это проверка интеграции, а не обнаружение объекта.

Изучены предоставленные `datainfo` PDF-руководство FITS v4.00, supporting document,
оба англоязычных tutorial notebook и лицензия tutorial. Документы и архивы данных
остаются локальными; код notebook не копировался в адаптер.

- [CADC NEOSSat и описание продуктов](https://www.cadc-ccda.hia-iha.nrc-cnrc.gc.ca/en/neossat/).
- [CADC TAP](https://www4.cadc.hia.nrc.gc.ca/en/doc/tap/).
- [CSA ASTRO](https://data.asc-csa.gc.ca/users/OpenData_DonneesOuvertes/pub/NEOSSAT/ASTRO/)
  и [XML](https://donnees-data.asc-csa.gc.ca/users/OpenData_DonneesOuvertes/pub/NEOSSAT/XML/)
  остаются альтернативными каталогами. Рекурсивно скачивать их для поиска не требуется;
  приложение использует индекс публичных наблюдений CADC.

На странице CADC NEOSSat приведена официальная благодарность, необходимая для научных
публикаций с данными миссии. Ссылку на неё сохраняем в provenance результатов.
Доступность данных не означает одобрения приложения CSA, CADC или NASA.

Для фронтенда: `capabilities.supplemental_sources.neossat` перечисляет операции.
Общие поля `capabilities.provider/synthetic` описывают основной SPHEREx-режим;
для NEOSSat используйте `Observation.provider/synthetic` и `Job.request.source`.

Повторная live-проверка выявила ещё один узел CADC: ws-sf.canfar.net.
Разрешены подтверждённые перенаправления minoc на ws-cadc, ws-uv и ws-sf.canfar.net
только для пути коллекции NEOSSAT. Посторонние хосты и коллекции остаются запрещены.
