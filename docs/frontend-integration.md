# Интеграция интерфейса / задание для Gemini

Бэкенд и дизайн развиваются независимо. Реальные поля и типы берите из
`docs/openapi.json`; интерактивная версия — `http://localhost:8000/docs`.

## Локальная настройка

NEOSSat доступен с `source=neossat` в поиске и теле задачи, независимо от demo/irsa
основного источника. Поддерживаются cutout/blink; в задаче укажите
`subtract_zodi=false`, `reject_flags=0`. Единицы — отсчёты детектора.
Подробности и примеры: [neossat.md](neossat.md).

- API: `http://localhost:8000`, префикс `/api/v1`.
- Разрешённые адреса фронтенда: `http://localhost:3000` и `http://localhost:5173`.
- Другой адрес добавляется в `SPHEREX_CORS_ORIGINS` (JSON-массив в `.env`).
- В Vite можно использовать `VITE_API_BASE_URL=http://localhost:8000`.
- API и worker должны быть запущены одновременно. Без worker задачи останутся `queued`.
- Перед отображением данных вызывайте `/api/v1/capabilities`; в demo показывайте
  постоянную заметную подпись «Синтетические демонстрационные данные».

## Основной сценарий

Для Spectral Lab есть координатная задача `kind=spectrum` с пустым observation_ids.
После succeeded типизированный результат доступен по `GET /api/v1/jobs/{id}/spectrum`.
Отображаются 102 слоя DR1 с реальными длинами волн, физическими MJy/sr и качеством;
пропуски не интерполируются, ошибки остаются null. Модели находятся в справочном блоке.
[Метод, ограничения и пример API](spectra.md).

Для стартовых кнопок пяти объектов из условия используйте `GET /api/v1/targets`.
Поля `ra`, `dec`, `radius_deg` подходят для поиска, `fov_deg` — для создания задачи.
Показывайте `notes`: координаты являются центрами полей, без переноса на дату наблюдения.

1. Пользователь вводит RA `[0, 360)`, Dec `[-90, 90]` в градусах ICRS.
2. Поиск: `GET /api/v1/observations?ra=10&dec=20&radius_deg=0.05`.
   Для одного детектора SPHEREx добавьте `detector=1…6` до получения ограниченной
   выборки. Для NEOSSat этот параметр недопустим. `mjd_min`/`mjd_max` сужают время.
3. Показать список/таймлайн с `mjd_start`, `detector`, диапазоном волн и коллекцией.
   `null` означает отсутствие метаданных, а не нулевое значение.
4. По ID из ответа отправить задачу с `ra`, `dec`, `fov_deg`, `size_px`.
5. Получить `202 Accepted` и `id`, показывать `queued`/`running`.
6. Проверять `/api/v1/jobs/{id}` примерно раз в 2 секунды. Остановить опрос при
   `succeeded` или `failed`, отменять запросы при уходе пользователя со страницы.
7. Для `succeeded` показать PNG или GIF из `artifacts`; предложить FITS и provenance JSON.
   При `failed` показать `error`. Текст предупреждений `warnings` доступен рядом с результатом.

`difference` принимает **[reference, science]**, результат — science − reference.
`blink` сортирует кадры по времени; `stack` и `difference` требуют один детектор.
`cutout` принимает ровно один ID; `stack`/`blink` — 2–12; `difference` — ровно два.

`radius_deg` — круг поиска; `fov_deg` — сторона итогового изображения. Верхние
ограничения возвращаются в capabilities. `size_px` меняет размер сетки, а не разрешение телескопа.
FITS содержит линейные значения; PNG/GIF используют растяжение яркости для просмотра.

## URL и встраивание

Фронтенд поддерживает ссылки вида `/?ra=10&dec=20&fov=0.1&radius=0.01&band=SPHEREx-D4#explorer`:
прочитать параметры и заполнить форму; в текущем интерфейсе запрос запускается кнопкой. Бэкенд уже принимает
координаты через GET, но страницу по такой ссылке реализует фронтенд.
`source=spherex|neossat` сохраняет источник; `band` применяется только к SPHEREx.
Параметры ссылки заполняют форму без автоматического сетевого запроса. Выполненный
ручной поиск обновляет координаты общего выбранного поля и ссылку.
Ссылки `artifacts[].url` относятся к **бэкенду**, а не к адресу фронтенда.

Пример с клиентом из `packages/api-client/src/index.ts`:

```typescript
const api = createSpherexClient(import.meta.env.VITE_API_BASE_URL);
const search = await api.search({ ra: 10, dec: 20 });
const selected = search.observations.filter(o => o.detector === 1);
const job = await api.createJob({
  kind: "blink",
  observation_ids: selected.slice(0, 2).map(o => o.id),
  ra: 10, dec: 20,
});
// После опроса getJob(job.id): <img src={api.artifactUrl(artifact)} />
```

Клиент написан на TypeScript без рабочих зависимостей. Типы `schema.d.ts` генерируются
стандартным `openapi-typescript`; после изменения API:

```text
uv run python scripts/export_openapi.py
cd packages/api-client
npm ci
npm run generate
npm run check
```

## Состояния и ошибки

| Ситуация | Поведение интерфейса |
| --- | --- |
| Нет наблюдений | Показать пустое состояние; предложить другое поле/время |
| `possibly_truncated=true` | Предупредить о неполной выборке, предложить сузить поиск |
| HTTP 422 | Показать ошибку параметров; не повторять запрос автоматически |
| HTTP 429 | Очередь заполнена; учитывать `Retry-After` |
| HTTP 502 | Архив недоступен; предложить повторить поиск |
| Задача долго `queued` | Сообщить об ожидании обработки; проверить запуск worker |
| `status=failed` | Показать `error`, разрешить изменить параметры и создать новую задачу |

Ошибки API имеют `error.code`, `error.message`, `error.details`, `error.request_id`.
Доступны заголовки `X-Request-ID`, `Location`, `Retry-After`.
Готовые результаты публичны для пользователей этого экземпляра: персональных аккаунтов пока нет.

## Что пока не изображать как рабочую функцию

Калиброванная фотометрия источника, Gaia/WISE overlays,
автоматическое обнаружение Planet X/движущихся источников и научно согласованные
по длинам волн разности пока не реализованы. Их статус есть в `capabilities.planned`.
Дизайн может предусмотреть эти панели, но должен явно показывать, что они ещё недоступны.

## Исправления интеграции Demotest1

Dev-фронтенд использует относительные `/api` URL и Vite proxy. В общем запуске
`VITE_API_PROXY_TARGET` автоматически совпадает с выбранным PORT бэкенда.
Header показывает отсутствие API вместо подстановки demo capabilities.
Sky Explorer очищает выбор при смене источника, отменяет старые запросы, ограничивает
выбор 12 кадрами и останавливает опрос при уходе со страницы. Ошибки поиска, отправки
и обработки отображаются вместе с предупреждениями API; фиктивных успешных задач нет.
Тела задач используют координаты завершённого поиска, а не изменённой после него формы.
NEOSSat stack/difference недоступны; разность SPHEREx обозначена science minus reference.
Локальные изображения карусели помечены как синтетические, спектральная панель — прототип.

Повторная проверка Demotest1: добавлены шесть DOM-тестов Sky Explorer (ошибки поиска
и отправки, смена миссии/цели, запоздавший ответ, ошибка worker и координаты задачи).
Смена миссии или цели начинает отдельную сессию компонента с отменой старых запросов.
Эти тесты запускаются в GitHub Actions через `npm test`.

## Demotest1NonFix: реальный режим

Ветка запускает SPHEREx с IRSA по умолчанию и открывает Sky Explorer первой вкладкой.
`capabilities.provider=irsa`, `capabilities.synthetic=false` описывают основной источник;
синтетические иллюстрации карусели отдельно помечены и не используются как результат поиска.
Для существующей установки необходимо переключить `.env` с demo на irsa и перезапустить
API вместе с worker. Поддержка синтетических данных сохраняется только как явный режим
для тестов; недоступность IRSA не активирует его автоматически.

## Mission Control: реализованные экраны

`App` хранит выбранное поле, режим и общий `usePipeline`. Переход между режимами
сохраняет поиск/задачу; смена поля или миссии сбрасывает выбор и отменяет старые запросы.
`usePipeline` отвечает за поиск, отправку, опрос, ошибки и ограниченную историю результатов.
HTTP-контракт остаётся в типизированном `api/client.ts` и пакете API client.

Comparator создаёт blink для двух реальных наблюдений и использует `frame-00/01.png`;
разность создаётся отдельной задачей. FITS-инспектор читает карточки IMAGE из самого
файла. Нет изображений по умолчанию или подмены при ошибках. Карусель — координатные
карточки без прежних синтетических изображений. Поля не перенесены по proper motion.

Спектральная вкладка отделена от измерений: Planck Fλ и форма солнечного спектра
нормированы независимо. CSV содержит модели. Молекулярные окна — ориентиры;
102 равномерных отсчёта не являются таблицей калиброванных каналов.

Звук включается пользователем. У 3D-потока есть пауза; предпочтение reduced motion
отключает декоративные анимации. При отсутствии WebGL остаются статическая схема
и доступные с клавиатуры кнопки всех целей. Орбита и фон не являются эфемеридами.

## Исправления IDKWht2do

Опрос старой задачи отменяется синхронно при новом поиске, отправке или сбросе сессии.
Поздний ответ не может вернуть старое изображение. Источник NEOSSat сохраняется при
быстром выборе цели и переходах между режимами; повторный клик на текущий источник
не сбрасывает результаты. Навигация Back/Forward между режимами одного поля также
сохраняет pipeline; смена координат/источника/параметров очищает его.

Archive detector ограничивает запрос к архиву, Display detector — только таблицу.
Для SIA используется внутренняя длина волны диапазона выбранного детектора, затем
проверяется точный номер детектора и пересечение пользовательского диапазона по
метаданным ответа. Это выбор файлов, а не спектральный канал пикселя.
Дубликаты и отфильтрованные строки не скрывают достижение MAXREC: предупреждение
`possibly_truncated` остаётся консервативным. Сузьте время при неполной выборке.

Comparator учитывает пару, направление разности и FOV при подборе готовых результатов.
Ссылки FITS поддерживают CORS с заголовком Range при отдельном адресе API.
После 30 секунд в queued интерфейс напоминает проверить worker; задача не объявляется
успешной по таймеру. В футере присутствуют acknowledgement и ссылка на SPHEREx/IRSA.


## Совместимость после исправлений бэкенда Demotest1(11)

Файлы интерфейса и форматы SkySearch/JobRequest/Job/SpectrumResult не менялись.
POST /api/v1/jobs по-прежнему отвечает 202; одинаковый запрос может вернуть
существующий ID активной задачи или готового результата из кратковременного кеша.
Не следует считать каждый POST обязательно новой задачей. Статусы задач прежние:
queued/running/succeeded/failed.

HTTP 502 сохраняет стандартную оболочку error. Поле code уточняет причину:
archive_rate_limited, archive_timeout, archive_not_found, archive_rejected,
archive_denied, archive_connection_error, archive_http_error или archive_error.
Retry-After передаётся, если архив указал срок ожидания. Текст error.message
и ошибки задачи содержит контекст и может показываться существующим интерфейсом.

/health/ready теперь возвращает 503 без работающего worker с той же конфигурацией.
Это не проверка доступности IRSA. /health/live остаётся независимой проверкой API.
